# Frontend Admin Panel - Endpoint Integration Guide

## Overview
The admin frontend has been updated to work seamlessly with the Fee Management System API endpoints. All CRUD operations for Students, Classes, Class Fees, Fee Payments, Receipts, and Users are now properly configured.

**Users Table**

### 4. Data Table Component (`src/components/datatable/Datatable.jsx`)

## API Endpoint Configuration

### Base URL
```
http://localhost:3000/api
```

### Available Endpoints

#### Users
- `GET /users` - Get all users
- `GET /users/:id` - Get single user

#### Students
- `GET /students` - Get all students
- `GET /students/:id` - Get single student
- `POST /students` - Create student
- `PATCH /students/:id` - Update student
- `DELETE /students/:id` - Delete student

#### Classes
- `GET /classes` - Get all classes
- `GET /classes/:id` - Get single class
- `POST /classes` - Create class (requires: className)
- `PATCH /classes/:id` - Update class
- `DELETE /classes/:id` - Delete class

#### Class Fees
- `GET /class-fees` - Get all class fees
- `GET /class-fees/:id` - Get single class fee
- `POST /class-fees` - Create class fee
- `PATCH /class-fees/:id` - Update class fee
- `DELETE /class-fees/:id` - Delete class fee

#### Fee Payments
- `GET /fee-payments` - Get all fee payments
- `GET /fee-payments/:id` - Get single fee payment
- `POST /fee-payments` - Create fee payment
- `PATCH /fee-payments/:id` - Update fee payment
- `DELETE /fee-payments/:id` - Delete fee payment

#### Receipts
- `GET /receipts` - Get all receipts
- `GET /receipts/:id` - Get single receipt
- `POST /receipts` - Create receipt
- `PATCH /receipts/:id` - Update receipt
- `DELETE /receipts/:id` - Delete receipt

## Data Flow

### Create Form Flow
1. User navigates to `/[resource]/new`
2. New component loads
3. useFetch hooks load classes, students, and fee payments from API
4. Select dropdowns are populated dynamically
5. User fills form and submits
6. API POST request creates resource
7. User is redirected to resource list view

### List View Flow
1. User navigates to `/[resource]`
2. List component renders
3. Datatable requests data from API endpoint
4. useFetch hook retrieves array of items
5. Data is mapped to ensure id field exists
6. DataGrid renders with columns from datatablesource
7. Users can view, search, and delete items

### Detail View Flow
1. User clicks View button on item in list
2. Navigates to `/[resource]/search/:id`
3. Single component loads
4. useFetch hooks retrieves single item details
5. Item details are displayed
6. User can edit (for non-deleted items) and save changes

## Error Handling

### API Error Handling
- HTTP errors are caught and displayed to user
- 404 errors are handled gracefully without logging
- Error messages from API response are displayed in UI
- Form submission errors show in error div with red background

### Data Validation
- useFetch validates response is array before processing
- Datatable checks data structure before rendering
- Form inputs validate based on input type (number, date, etc.)

### Common Issues and Solutions

**Issue: Select dropdowns are empty**
- Ensure API is running on http://localhost:3000
- Check browser console for fetch errors
- Verify API endpoints are returning data

**Issue: Student names not showing in payments list**
- Check that student object is being populated in API response
- Verify student?.fullName field access in renderCell

**Issue: Create form not submitting**
- Check that all required fields are filled
- Look at browser console for error messages
- Verify form field names match API schema

**Issue: Lists showing "Loading data..." indefinitely**
- Check API server is running
- Look for CORS errors in browser console
- Verify database has sample data
